# MIR Remote

> 手机上打开一个网址 → 选引擎 → 写词 → 出歌 → 直接听、直接下载歌和谱。

**算力全在你家这台电脑上。** 手机只干三件事：发指令、看进度、收结果。
它不联网调云端、不花钱、不排队等别人。

定位一句话：**远端回收生成结构、给出生成要求的遥控镜子。**
镜子只反射结果，不反射过程；但等待是真的，所以等待得有人管。

## 一、怎么开

### 平时用（推荐）

双击 `start.command`。它会：

1. 起服务（`0.0.0.0:7871`，局域网和 Tailscale 两个口都听）
2. 把**两个地址**和**配对码**打在窗口里
3. **窗口可以直接关掉，服务留在后台**（起不来就照实把日志尾巴打出来）

起来之后屏幕上长这样：

```
MIR Remote 已开。

  在家里（同一个 WiFi）：http://192.168.31.208:7871
  在外面（Tailscale）：  http://100.110.118.100:7871
  配对码：123456

（这个窗口可以直接关掉，服务还在后台跑）
```

⚠️ **局域网那个地址是会变的**（路由器给的），Tailscale 那个不会变。
所以出门在外、或者在家懒得看地址，**用 Tailscale 那条最省事**。

### 命令行

```sh
python3 mir-remote/server.py
```

可选环境变量：

| 变量 | 默认 | 意思 |
|---|---|---|
| `MIR_PORT` | 7871 | 端口 |
| `MIR_HOST` | 0.0.0.0 | 听哪个网卡（0.0.0.0 = 局域网都能连） |
| `MIR_SONGS_DIR` | `/Volumes/REBIRTH/MI/Songs` | 作品存哪（外盘，见下面「作品落盘」） |

## 二、手机上怎么用

### 两条路，随便挑

**① 浏览器**（不装东西）：手机连同一个 WiFi → 打开窗口里打的那个「在家里」地址
（`http://192.168.31.xxx:7871`，以窗口为准）→ 第一次填 6 位配对码 → 选引擎、写词、出歌。

**② 装成 App**（安卓）：手机打开同一个地址加 `/app`
（或扫那一页上的二维码）→ 下载安装 → 打开填一次配对码。
App 会自己先试「出门地址」、再试「家里地址」，连不上会给一句人话和一个「换地址」按钮。
安装包是**自己打的**（`tools/build.sh`，复用 voicecasterrecorder 那套工具链），
提示「未知来源」就允许。

> iOS 不用装 App：把分享链接发到 iOS 微信，点开就能听、能下（在浏览器里打开更顺）。

### 出了以后

下载到手机，用微信发出去就行。两档地址都是 `http://`，浏览器在这种情况下
**调不出系统分享面板**，这是浏览器的规矩，不是按钮坏了。

**分享页**（`/s/<id>`）把**歌**和**谱子**分开列，每个按钮标了大小和用途
（mp3 直接听/转发、原文件要精修、谱子可进 Dorico）—— 让人自己挑下哪个。

⚠️ **「复制分享链接」在 http 下不能用 `navigator.clipboard`**（浏览器只认 https/localhost），
2026-11-17 用户实测「点了没反应」就是这个原因。现在的兜底是 `execCommand('copy')`，
再不行会弹出一个**可以长按复制**的链接框。

## 二·五、乐谱（2026-11-19 加）

底部多了一个 **「乐谱」** 页：选「时期 → 作曲家 → 编制」，点「写谱」，
出来是 **MusicXML**（能直接进 Dorico）。

- 名单是电脑上曲谱工作台自己报的（112 种组合：3 个时期 / 62 位作曲家 / 6 种编制）。
- 进度条按"已经写了多少字"估——它不报总量，所以字数是真实数量，百分比是估的。
- 写完可以**下载谱子**，也可以点「复制分享链接」发微信（链接页里有下载按钮）。
- 一首大约 5–10 分钟（看编制）。这比出歌慢得多，是模型本身的节奏。
- 谱子是**草稿**：学的是"像谁"，不是"能出版"，结构和细节进 Dorico 再改。
- ⚠️ 第一版转换有时会挂（跨谱表的键盘/管风琴谱），已加清洗重试；
  仍失败时会明说，不会假装成功。

## 三、引擎（2026-11-19 起两台）

| 手机上叫 | 出来什么 | 大概多久 |
|---|---|---|
| **成曲**（ACE-Step） | wav，能唱也能纯器乐（48 kHz 立体声） | 90 秒的歌约 30 秒出 |
| **写歌**（YuE2） | flac + abc 谱 + MusicXML（可进 Dorico） | 快档约 5 分钟 |

- **成曲**换成了本机 MLX 上的 ACE-Step 1.5 XL Turbo 8bit：8 步、峰值内存约 10.5 GB。
  手机上的中文风格按钮（流行女声/民谣/古风…）由服务端翻成写全的英文描述再发 ——
  这个移植**没有官方的 LM 扩写**，短标签会出来得比较平。
- **人声草稿**（HeartMuLa）与**纯音乐**（Stable Audio）已从遥控器撤下：
  前者退役，后者归创作台做氛围配乐。
- 时长上限：成曲 **600 秒**，写歌按档位。

**下载谱子只在「写歌」那一档出现**，其余只给歌。

引擎是**开机自检**的：哪台没装好，界面上那格会变灰并写明缺什么。
遥控器完全照 `/v1/info` 画界面 —— 换一台只有两台引擎的电脑，界面自动少两格。
（`/v1/info` 检查的是**引擎本体 + 模型**；只查引擎本体的话，ACE-Step 会显示可用、一点就失败 —— 2026-11-17 修过。）

## 四、一页纸协议（给做别的平台版本的人）

整套东西就是 **HTTP + JSON + Bearer token**。没有自定义二进制协议、没有自己写的加密握手。

| 说什么 | 接口 | 内容 |
|---|---|---|
| 我是谁、能干什么 | `GET /v1/info` | 名字、平台、版本、**引擎清单**（每台：id、显示名、参数、能出什么产物） |
| 配对 | `POST /v1/pair` | `{"code":"123456"}` → `{"token":"…"}`；之后每次请求带 `Authorization: Bearer <token>` |
| 出歌 | `POST /v1/jobs` | `{"engine":"yue2","title":"","lyrics":"…","style":"…","steps":8}` → `{"id":"…"}` |
| 看进度 | `GET /v1/jobs/<id>` | `{"percent":42,"state":"running","message":"…","eta_seconds":180,"outputs":[…]}` |
| 停 | `POST /v1/jobs/<id>/cancel` | —— |
| 拿文件 | `GET /v1/jobs/<id>/files/<名字>` | 直接下载（支持 Range） |
| 作品库 | `GET /v1/songs` | 出过的每一首 |
| 分享页 | `GET /s/<id>` | 不用 token，链接本身就是钥匙 |

`GET /v1/info` 是**全部的钥匙**：后端自己说清有什么，遥控器根本不需要知道对面是 Mac 还是 Windows。

### 三条硬规矩

1. **`local` 必须诚实**：每台引擎都要标明是不是本机推理。偷偷调云端 =
   把这套东西的价值抽掉，不接受。
2. **能力协商，别写死**：遥控器照 `/v1/info` 画界面，没有的就不显示、不认识的跳过，不能崩。
3. **带版本号**：路径写 `/v1/`。改协议就开 `/v2/`，老遥控器还能用。

### 自己验一遍

```sh
python3 mir-remote/tools/probe.py http://192.168.31.99:7871 --code 123456
python3 mir-remote/tools/probe.py http://192.168.31.99:7871 --code 123456 --full
```

`--full` 会真的跑一首最短的歌（占几分钟本机算力），逐项打勾。
**你的实现合不合格，这个脚本告诉你，不用来问人。**

## 五、在家 / 出门：两层门槛

| 用在哪 | 需要什么 | 门槛 |
|---|---|---|
| **在家**（手机连自家 WiFi） | 什么都不用 | **零** |
| **出门**（人在学校 / 外面） | 一条「回家的路」 | 要装 / 要配 |

**入门的说法是「在家」那条：装好、打开就能用，不装任何东西。**
「出门」是可选升级，不是前提。

出门那条路，三档可选，**不绑死任何一家**：

1. **Tailscale** —— 我这台在用；但要能连上它的登录服务器，有些网络就是不行。
2. **ZeroTier / 蒲公英 / 花生壳** —— 国内更好连的同类。
3. **公网 IPv6 直连** —— 理论零安装，但要路由器放行、运营商给地址
   （⚠️ 2026-11-17 实测：这台机器现在没有公网 IPv6）。

**关键实现决定：地址栏填什么都能用。** 因为整套协议就是 HTTP，后端不认识路、只认地址：

- 局域网 `http://192.168.31.99:7871`
- Tailscale `http://100.110.118.100:7871`
- 穿透服务给的外网地址
- IPv6 `http://[2xxx:…]:7871`

⇒ **换穿透方案不用改一行代码**，填个新地址就行。

## 六、不做什么（判据留着，别再想一遍）

- **不建公网门、不碰 Tailscale Funnel。**
  转发渠道是现成的（微信、网盘），比自己维护一个公网服务省事也不花钱；
  公网门等于把家里这台电脑的端口挂到外网给人访问，为一个「发首歌」不值当。
- **不改 MIR 本体。** 这个服务只复用引擎的 adapter 契约
  （`params.json` 进、`progress.json` 出、看退出码），**不碰 SwiftUI 代码**。
  将来要在手机上改谱、送 ACE / Live，那是另一件事，单独定。
- **不做「插件市场」那类东西。**

## 七、作品落盘

```
/Volumes/REBIRTH/MI/Songs/<20261117-101200> <标题>/
    <标题>-1分29秒.mp3        ← 试听 / 转发（优先）
    <标题>-1分29秒.flac       ← 原文件（要精修再下）
    <标题>-1分29秒.abc        ← 谱（只有「写歌」那档有）
    <标题>-1分29秒.musicxml   ← 谱，给 Dorico
```

作品库在 `mir-remote/state/songs.json`。

⚠️ **外盘没插时，出歌会被拒，并明说「外盘没插」** ——
绝不静默改存到本地：那样人会以为东西在外盘上，等插盘去找却找不到。

---

## 八、排队：一次只跑一首

引擎吃内存（35B 级模型 + 音频推理），两首同时跑会把机器撑爆。
所以：

- 遥控器这边的任务**串行**排队；
- **MIR 界面正在跑时，遥控器会等**（看它的进度文件还在不在动）；
- 跑歌期间自动 `caffeinate`，跑完撒手。

## 八·五、它依赖什么（2026-11-17 用户确认的）

**只依赖这个服务本身，跟 DSH 无关。**

- 电脑上双击 `start.command` → 服务在后台跑（`nohup`），**关掉终端、关掉 DSH 都不影响**。
- **在家**：手机连同一个 WiFi，打开「在家里」那个地址就行，**不用 Tailscale**。
- **在外面**：电脑和手机都开 **Tailscale**，用「在外面」那个地址（`100.110.118.100:7871`）。
- 电脑重启 / 服务关掉了：**再双击一次 `start.command`**。
  **★ 2026-11-19 实测：做不到开机自启，别再试了。**
  试过 launchd（`~/Library/LaunchAgents/com.jieda.mir-remote.plist`），
  每 15 秒失败一次，日志刷了 576 KB，错误永远是
  `can't open file …server.py: [Errno 1] Operation not permitted` ——
  macOS 的隐私保护不让后台进程读「文稿」目录。那条 plist 已经卸掉存档在
  `state/com.jieda.mir-remote.plist.disabled`。
  **要真自启，只有一条路：给后台程序授「完全磁盘访问权限」**（要人点一次系统设置）。
  **症状对照**：手机报「连不上电脑」，但 Tailscale 里两台设备都是绿的 ——
  **那不是网络的事，是电脑上这个服务没开**。

同理，手机录音（voicecasterrecorder）那条也只依赖 VoiceCaster.app，不依赖 DSH。

## 九、踩过的坑（写给下一个改它的人）

1. **手机 `<audio>` 必须支持 Range** —— iOS 的音频元素不播一个不支持
   `Range` 的链接。下载接口按字节区间返回 206。
2. **PATH 只有 `/usr/bin:/bin:…`** —— `ffmpeg` 住在 `/opt/homebrew/bin`，
   代码里按绝对路径找（`find_tool`）。
3. **`ps` 在某些沙箱里会被拒**（`Operation not permitted`）——
   所以「MIR 界面在不在跑」先看它的 `output/progress.json` 还在不在动，
   `ps` 只当兜底。
4. **配对码只有 6 位**，得挡住猜：每 IP 每分钟 8 次。
5. **引擎产物要按 `progress.json` 点名的为准** —— adapter 最清楚哪份是主音频，
   目录里还可能躺着分段小文件。
6. **文件名规则跟 MIR 本体一致**（斜杠、冒号换下划线，截 40 字），
   两边各有一份实现，改一边要跑 `gui/check-naming.sh`。
7. **别在受限的沙箱里（比如从 DSH 里起）跑这个服务测 Stable Audio** ——
   它的服务要写 `~/AI-Studio/app/`，沙箱一拦就起不来，表现是「正在把 Stable Audio
   叫起来…」然后 120 秒后失败。**用户双击 `start.command` 起没有这个限制。**
8. **收集成品失败时不要删成品目录** —— 2026-11-17 实际踩到：外盘写不进去，
   代码把整个 out 目录清掉了，白跑一首五分钟的歌。现在的规矩是：
   成功才清，失败留着让人去电脑上看。
9. **App 探测超时只有 2.5 秒，从外面经 Tailscale 绕一圈常常不够**
   （2026-11-19 实测：同一台手机，手填地址能连，App 自己探测两个候选全判失败；
   用户当场点透了：**这是概率事件**，同一时刻点两次，一次通一次不通）。
   表现是「明明通了、App 还是说连不上」，而这台电脑的日志里能看到
   `ConnectionResetError: Errno 54`（客户端等不及先断了）。
   **改法（2026-11-19 已落地）**：连接超时 2.5 秒 → **15 秒**、读超时 **10 秒**
   （连不上的等待给足，连上之后等数据收短一点）、两个候选**并行**试（谁先回用谁）、
   失败**自动再来一轮**，成功立刻返回。⚠️ 改完必须重打包 + 手机上重装一次。
   判据：电脑的 `state/requests.log` 里出现 `CONN/REQ 200` 说明手机真的到了，
   这时候还报「连不上」就一定是客户端等不及走的 —— 别再往网络那头猜。
10. **要知道手机现在走的是哪条路：看这台电脑上的连接对端**
    —— `lsof -nP -iTCP:7871` 里如果对端是 `100.x.x.x` 就是 Tailscale，
    `192.168.x.x` 就是同一个 WiFi。2026-11-19 靠这一条直接定案，
    不用去问手机那边填了什么。

11. **给手机传安装包，别绕那条不稳的网络** —— 2026-11-19 实测：微信内置浏览器
    会拦 APK 下载（一直转圈），Tailscale 链路又时通时不通。用户是经 **DASHGO** 远程连
    DSH 的，**最有效的是 DSH 的 present 卡片**（文件卡点一下就到手机上）。
    二维码只适合同一网络里的旁观者扫，别当成主力通道。
